# 최신화 파이프라인

Harrison 19판 원문을 주장(claim) 단위로 쪼개고, 주장마다 최신 근거와 대조한 뒤, AI가 쓸 수 있는 말뭉치로 다시 만드는 절차다.

```
by_chapter/*.md  (19판 원문, 수정 금지)
      │ ① 임상 주장 추출 + 원문 위치
      ▼
claims/<장>.yaml ◀── sources/registry.yaml (출처 레지스트리, 단일 정의)
      │ ② tools/build_corpus.py (검증 → 생성)
      ├─▶ updated/<장>_<제목>.md   사람이 읽는 최신화 문서(원문 요지·최신 내용·출처·충돌)
      ├─▶ corpus/*.jsonl           AI·규칙 엔진용 말뭉치(항목마다 concepts 필드)
      └─▶ corpus/{test_concepts,drug_concepts,drug_classes}.jsonl
                                   검사·약제 개념별 재정리 ◀── mappings/{tests,drugs}.yaml
```

`claims/*.yaml`, `sources/registry.yaml`, `mappings/*.yaml`만 직접 수정한다. `updated/`와 `corpus/`는 생성물이다. 검사·약제 매핑은 [mappings/README.md](../mappings/README.md)를 본다.

```bash
uv run --with pyyaml python text_data/tools/build_corpus.py          # 검증 + 생성
uv run --with pyyaml python text_data/tools/build_corpus.py --check  # 검증만
# 말뭉치가 바뀌었으면 사전 계산 임베딩도 갱신(KURE-v1 임베딩 서버 필요, 바뀐 문단만 계산)
uv run python text_data/tools/build_embeddings.py --embedding-url http://127.0.0.1:18080 --generator "TEI cpu-1.9.4"
```

## 주장 스키마

| 필드 | 의미 |
| --- | --- |
| `id` | `<장>-C<번호>` (보충 장은 `S01-C01`처럼 `S<번호>`) |
| `type` | diagnosis · workup · treatment · dose · threshold · monitoring · referral · formula |
| `original.text` / `location` | 19판 원문 요지와 위치(파일·행). PDF 쪽은 생성기가 원문 표시로 자동 계산. 보충 장은 두지 않는다 |
| `status` | 유지 · 개정 · 보완(원문에 없던 최신 권고) · 폐기 · 확인불가 |
| `current.text` / `sources` | **AI 사용 가능 내용. A등급 출처만 인용 가능**(위반 시 검증 실패) |
| `reference.text` / `sources` | B·C·U등급 근거(허가 필요). 사람 검토용이며 AI 말뭉치에 들어가지 않음 |
| `verification` | current의 확인 수준: primary · secondary · local_db · unverified(current 없으면 unverified) |
| `conflicts` | 지침 사이, 지침과 국내 허가사항 사이의 차이 |
| `review.status` | draft → approved/rejected. **의료진 검수 후에만 approved**, A등급 근거가 없으면 approved 불가 |
| `corpus` | current 근거로 만든 구조화 항목 → `ai_tier: A` |
| `reference_corpus` | reference 근거만 있는 구조화 항목 → `ai_tier: permission_required` |

출처 등급(`sources/registry.yaml`의 `ai_use`, AX-G AI는 상업 서비스 기준):

| 등급 | 의미 | 예 |
| --- | --- | --- |
| A | 출처를 밝히고 상업 AI에 사용 가능 | VA/DoD 지침, NIH(NIDDK·LiverTox), CDC, openFDA 허가사항(CC0) |
| B | 비상업·변경금지 조건 | KDIGO 빈혈(CC BY-NC-ND), StatPearls, 국가건강정보포털(공공누리 4유형) |
| C | 권리자 허가 필요 | ADA(TDM·ML 금지), NICE(AI 별도 라이선스), KDIGO 지침, USPSTF(영리 이용 허가), Harrison |
| U | 조건 미확인(허가 필요로 취급) | 대한당뇨병학회 지침, 로컬 약품 DB(medicine_dict.pkl 출처 미상) |

`usable`(운영 AI 사용 가능) = `ai_tier: A` 이고 `approved` 이고 verification이 primary 또는 local_db 이고 status가 폐기·확인불가가 아님. 로더(`clinical_corpus.py`)는 여기에 더해 레코드의 모든 출처가 A등급인지 다시 확인한다. 현재 모든 항목은 draft라 `usable: false`다.

openFDA 허가사항은 `tools/fetch_openfda_label.py`로 받아 `sources/raw/openfda/`에 버전(set_id·version·effective_time)과 함께 저장한다.

## 말뭉치 파일

| 파일 | 용도 | 예 |
| --- | --- | --- |
| `diagnosis.jsonl` | 진단 기준(조건식) | CKD, DKA, HHS |
| `workup.jsonl` | 상황별 권장 검사·주기 | CKD 빈혈 검사 주기, HbA1c 주기 |
| `treatment.jsonl` | 조건별 치료 권고·회피 | eGFR·UACR별 RAS 억제제/SGLT2i, ACEi+ARB 병합 금지 |
| `dose_rules.jsonl` | 성분별 신기능·칼륨 구간 용량 | DR-METFORMIN, DR-FINERENONE, DR-INSULIN-DKA-HHS |
| `lab_thresholds.jsonl` | 검사값 해석 구간 | eGFR G1–G5, UACR A1–A3, HbA1c 목표 |
| `formulas.jsonl` | 계산식(코드로 구현할 대상) | CKD-EPI 2021, eAG |
| `monitoring.jsonl` | 약 시작 후 추적 규칙 | RAS 억제제 시작 후 2–4주 Cr·K |
| `referral.jsonl` | 의뢰 기준 | 신장내과 의뢰 |
| `chunks.jsonl` | 근거 검색(RAG)용 청크 | 주장 1건 = 청크 1개 |

### 조건식

```json
{"all": [{"dx": "E11"}, {"var": "eGFR", "op": ">=", "value": 20}]}
```

- `all` / `any` / `not` 조합
- `var`: 수치 변수(`eGFR`, `UACR`, `K`, `HCO3`, `Hb`, `Ferritin`, `TSAT`, `HbA1c`, `Glucose`, `BHB`, `pH`, `age` 등)
- `dx`: KCD 코드 접두(예 `E11`, `N18`, `I50`) · `med` / `med_class`: 현재 처방 성분·계열
- `finding` / `event` / `risk`: EMR에 아직 없는 임상 정보. 연동 시 입력 경로를 정해야 한다.

## AI 연동 시 필요한 것

완료:
- **계산식**: CKD-EPI 2021 eGFR과 GFR 범주를 [clinical_calculations.py](../../src/ax_g_ai/services/clinical_calculations.py)에 구현. `calculationContext`에 연령·성별·혈청 크레아티닌이 있으면 `calculation_results`에 들어간다. eAG·KFRE는 미구현.
- **로더·평가기**: [clinical_corpus.py](../../src/ax_g_ai/services/clinical_corpus.py). 승인 조건(`usable`·`approved`·검증 수준·주장 상태)을 로드 시 다시 확인하고, 조건식은 3값 논리(값이 없으면 `None` = 입력 필요)로 평가한다. 생성기는 같은 조건식 문법을 검증한다.

- **1단계 근거 인용**: [clinical_evidence.py](../../src/ax_g_ai/services/clinical_evidence.py). 채팅 질문에 맞는 근거 문단을 출처·검수 표시와 함께 프롬프트와 API 응답(`evidence`)에 붙인다. 미검수 항목은 `AX_G_EVIDENCE_INCLUDE_UNREVIEWED=true`일 때만.
- **검사·약제 매핑**: [mappings/](../mappings/README.md) 개념 사전(LOINC·RxNorm 확인)과 [emr_mapping.py](../../src/ax_g_ai/services/emr_mapping.py)(EMR → `PatientFacts`). 말뭉치의 모든 검사·변수·약제 식별자가 개념으로 풀려야 빌드된다.

남은 일:
1. **병원 사이트 매핑**: 실제 검사·약품 마스터로 `tools/propose_site_map.py` 초안을 만들고 검사실·약제부 검수(단위·성분).
2. **런타임 연결**: 승인 항목이 생긴 뒤 환자 문맥(`PatientFacts`)을 만들어 평가 결과와 근거 청크를 프롬프트의 참조 영역에 넣는다. 용량 규칙 출력은 "검토 경고·참고 범위"로 표시하고 처방 용량으로 표시하지 않는다.

## 출처 지역 우선순위와 국내 기준 (2026-11-11)

출처 레지스트리의 모든 출처에 `region`(KR·US·EU·INTL)이 있다(없으면 빌드 실패). 우선순위는 **국내 > 미국 > 유럽 > 그 밖**이다.
같은 주제에 국내 기준을 넣을 때는 국내 주장에 `preferred_over: [국외 주장 id]`(주장 전체) 또는 corpus 항목의 `preferred_over: [항목 id]`(그 항목만)를 둔다.
생성기는 대상이 실제로 있는지, 국내 주장의 출처 지역이 대상보다 우선하는지 검사한다. 런타임은 대체된 국외 항목·근거를 `priority: reference`로 내려
권고로 쓰지 않고 참고(국내 기준과의 차이)로만 보여준다. 국내 기준이 없는 주제는 국외 기준이 그대로 권고가 된다.

## 보충 장 (S01~S04, 2026-11-11)

19판 원문(332~486장) 범위 밖이지만 추천 진단·검사에 필요한 영역을 보충 장으로 둔다. 장 파일에 `original_source: SUPPLEMENT`를 쓰면
생성기는 원문 위치 검사를 건너뛰는 대신 다음을 강제한다: 주장에 `original`을 두지 않고, `status`는 `보완`만, A등급 `current`가 반드시 있어야 한다.

| 장 | 출처(모두 A등급, 2026-11-11 원문 확인) |
| --- | --- |
| S01 순환기 | VA/DoD 고혈압 CPG 2026, 심부전 보편 정의 해설(Clin Cardiol 2022, CC BY), 오스트리아 심부전 철결핍 성명(2025, CC BY), 2024 ESC/EACTS 심방세동 지침 요약(Europace 2024, CC BY) |
| S02 호흡기 | VA/DoD COPD CPG 2026, VA/DoD 천식 CPG 2025 |
| S03 감염 | CDC STI 치료 지침 2021 선별 권고, CDC 결핵 검사·진단 안내(2025) |
| S04 암 검진 | CDC 대장암·폐암·유방암·자궁경부암 검진 안내, NCI 폐암 검진(전문가용) |

- CDC 검진 페이지는 USPSTF 권고를 재수록한다. USPSTF 원문(영리 이용 허가 필요)은 인용하지 않고 CDC 문장·사실만 쓴다.
- 미국 기준(연령·주기)이라 국내 국가검진·지침과 다를 수 있음을 각 주장의 `conflicts`에 적었다. 국내 기준 자료는 라이선스가 확인되지 않아 넣지 않았다.
- 증상 조합으로 만든 조건식(예: 호흡곤란+말초부종 → 심부전 평가)은 운영 가정이며 `notes`에 표시했다 — 검수 시 확정.
- 미확보: 위암 검진(내시경), 흉통·관상동맥질환 평가, 지역사회획득폐렴, 심부전 치료 — A등급 출처를 찾지 못했다.
